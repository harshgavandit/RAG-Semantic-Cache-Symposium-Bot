# Vercel deployment

The hosted version keeps the Python FastAPI retrieval/generation pipeline and adds a browser-native chat page. Streamlit remains the local interface. Vercel Functions do not serve Streamlit's WebSocket connection.

Deployment uses only the fictional, contact-free sample generated by `scripts/create_sample_pdf.py`. A build generates its PDF and verified FAISS/JSON index under `deploy_data/`; original `data/`, vector stores, `.env`, logs, caches and local environments are excluded from uploads. OpenAI embeddings are computed during the build with server-side credentials.

Upstash Redis provides both atomic admission and a bounded shared semantic answer cache for the hosted app. Each cache is scoped to corpus/model/prompt fingerprints. Secrets are stored as server-side Vercel environment variables. Requests are limited by the Vercel transport client identity and a shared provider-work budget.

Implementation and verification:

1. Add tests for the Redis cache, deployment configuration, build isolation and browser routes.
2. Implement hosted configuration and shared caching, retaining existing local behavior.
3. Add a responsive chat frontend with citations, cache badges and usable error states.
4. Run the complete regression suite and validate the deploy package contains no private document or credential files.
5. Deploy to Vercel, then test real generation, exact and paraphrase hits, unsupported questions, rate limits and the visible page at the public URL.

The hosted sample is a demo, not the user's private PDF. Live checks must establish provider access and shared Redis behavior; a successful build alone is not end-to-end proof.
